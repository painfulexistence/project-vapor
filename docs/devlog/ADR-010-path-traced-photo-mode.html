ADR-010: Path-Traced Photo Mode

2026-07-29 Adopted

Context

Every ray-traced effect in the engine so far is a correction applied to a rasterized frame: the G-buffer decides what is visible, and rays answer one narrow question about it — is this point in shadow, how occluded is it, what does this mirror see. That is the right trade for a game frame, and pillar three of the vision says so explicitly.

It also means the engine has never produced a ground-truth image. There is nothing to compare the hybrid path against. When a scene looks wrong, the question "is the approximation wrong, or is the input wrong?" has no reference answer, only other approximations.

A path-traced photo mode answers that. The camera stops, the same scene is integrated properly, and the result converges. It is both a feature (players take screenshots) and an instrument (the hybrid frame now has a reference to be measured against).

Decision

Add a progressive path tracer that runs as an alternate frame, not an extra pass. Photo mode owns its own RenderGraph; the gameplay graph is never rebuilt or cleared, so passes gameplay code appended through getRenderGraph() survive a round trip through photo mode.

Game frame PrePass -> LightCull -> RT shadow/AO/GI -> Main -> sky/fog -> │ composite tail │ Photo frame BuildAccelStructures -> PathTrace -> PathTraceResolve -> │ composite tail │

The composite tail — bloom pyramid, flare, tonemap/post-process, UI overlay — is shared verbatim between the two graphs. That is why the resolve kernel writes linear HDR into colorRT rather than presenting on its own: a photo then receives exactly the same grade and bloom the game does, and downstream passes need no idea which renderer produced the pixels.

Reuse over reinvention

The integrator allocates no scene data. It reads the TLAS, InstanceData, MaterialData, the merged vertex/index buffers and the bindless material texture table — all of which already exist for the raster and RT-reflection paths. Hit shading resolves normals, UVs and textures through the same user_instance_id → materialID → argument table chain 3d_raytrace_reflection.metal uses, because Metal's triangle intersector exposes no built-in hit normal.

Those inputs arrive through one struct, PathTraceSceneView, filled by the renderer each photo frame. The path tracer never reaches back into Renderer for anything. That one-way contract is what keeps photo mode from leaving traces in the scene layer — and it is what will let a headless CLI renderer drive the same integrator with no swapchain and no game loop.

The integrator

A single compute megakernel. Metal has no raygen/miss/hit shader tables (see ADR-008), so there is nothing to gain from a wavefront architecture here, and a megakernel keeps the whole light transport readable in one file.

  • Camera rays generated from invProj/invView with sub-pixel jitter. That jitter is the antialiasing — no MSAA, no TAA, the pixel integrates its own area.
  • Next-event estimation over every analytic light type, one shadow ray each, matching 3d_pbr_lib.metal's conventions so a converged photo is comparable with a raster frame of the same scene. Directional: cone-sampled sun disk. Point/spot: punctual, the raster path's inverse-square falloff windowed to zero at radius — which makes skipping lights beyond their radius exact, not a cutoff. Spot adds the squared cone ramp. Rect: true area sampling, uniform over the quad, double-sided like the raster polygon formula; shadow rays to positional lights are capped at the light's distance, since the light is not geometry and a wall behind it must not occlude it.
  • The rect radiance convention is derived, not guessed: emitting color · intensity / π makes the area estimator's expectation equal the raster path's Baum/Arvo solid-angle diffuse term — which is exact, so photo mode and raster agree on rect diffuse in expectation, and the raster's representative-point specular approximation becomes measurable against the true integral. That agreement is unit-tested: the MC area estimator and a transliterated Baum formula must match within 2%, front side and back.
  • No MIS anywhere, by construction: none of these lights exist in the TLAS, so a BSDF ray can never hit one — NEE is each light's only estimator. The cost is extra variance in sharp reflections of rect lights, which a hittable-emitter + MIS design would reduce.
  • BSDF importance sampling with lobe selection between Lambert diffuse and GGX specular. The specular lobe uses visible-normal (VNDF) sampling, whose weight collapses to F · G1(L) — no distribution term, no pdf division.
  • Russian roulette from the third bounce, scaling survivors by 1/p so the estimator stays unbiased.

Accumulation

Radiance sums into a full-resolution RGBA32F target: rgb is a running sum, alpha counts samples. 16-bit was rejected outright — at a few thousand samples a half-float mantissa stops resolving the newest contribution and the image silently stops converging, which is the worst possible failure mode for a feature whose entire promise is "leave it running and it gets better."

The RNG stream is keyed on (pixel, absolute sample index) only — never on frame number. N accumulated samples of a fixed camera therefore produce the same image every run. Reproducibility is what makes a render comparable against a reference; without it the instrument is useless as an instrument.

Invalidation

The accumulation state machine (PathTraceAccumulator) is deliberately pure logic with no GPU state, because its rules are the part of path tracing that is easy to get subtly wrong and impossible to see in a screenshot. An accumulator that fails to reset blends two different images together; one that resets too eagerly never converges. Neither failure crashes. Both silently ruin the render. It is unit-tested (test_path_tracer) on the CPU, with no device.

Any camera change invalidates. A coarse scene revision (drawable and light counts) catches models swapped and objects spawned. A material edit that changes a colour without changing those counts is not caught — that is what the panel's manual restart is for, and it is a documented gap rather than a hidden one.

Consequences

  • Metal only. The Vulkan backend reports no ray tracing, so the graph's RequiresRaytracing flags skip every photo-mode pass automatically and setPhotoModeEnabled refuses with a log line. The same Metal-first pattern as the rest of the RT chain.
  • CI cannot cover the image. rhi_metal.cpp forces capabilities.raytracing = false under GITHUB_ACTIONS, so only the CPU-side accumulation logic is testable there. Accepted: the alternative is no test at all.
  • colorRT gained TextureUsage::Storage so the resolve kernel can write it directly. This costs nothing on either backend and avoids an extra blit target plus its fullscreen pipeline.
  • Screen-space AO and god rays are parked on entry and restored on exit. PostProcess composites both unconditionally, and a stale AO buffer would multiply last raster frame's occlusion over an image that already computed occlusion exactly.
  • The photo frame carries no game UI. Canvas batches are drained, not drawn (gameplay keeps submitting them and only a flush resets the batch — without the explicit reset the vertex buffers grow for as long as the mode is open), and the photo graph drops the RmlUi overlay pass entirely. Note the captured EXR/PNG never contained UI regardless — capture reads the accumulator, upstream of all compositing — dropping the overlay makes the on-screen preview show what the file will hold. The ImGui overlay stays: it is the photo mode's control panel.
  • Dynamic geometry is invisible to it. Tessellated terrain, water and particles are not in the merged geometry or the BLAS set, so they do not appear in a photo. Accepted for a still-camera feature.

Known approximations

All deliberate, all stated in the kernel's header comment rather than left for a reader to discover:

  • The environment cube is the prefiltered IBL map, not a sharp capture. If the sky's sun disk survives prefiltering it is counted a second time on top of the analytic sun NEE. The disk is smeared across a 128 cube's mip 0 and the analytic sun dominates by orders of magnitude, so the error is small — but it is an error, and a sharp environment capture removes it.
  • Video-textured rect lights emit their flat colour, not the current video frame — the video texture is not bound in the kernel. Solid-colour rect lights (the common case) are exact per the convention above.
  • Light edits are caught by content, geometry edits are not. The photo frame hashes every light pool (FNV over positions, colours, cones, extents), so nudging a light in the inspector restarts the render automatically. Moving a mesh still leaves a stale accumulation — that remains the panel's manual restart.

What this unlocks

The integrator is decoupled from the swapchain and the game loop by construction. Status of the follow-ons:

  • Landed: HDR readback. RHI::copyTextureToBuffer blits the RGBA32F accumulator into a shared buffer with the same fencing as screenshots; the divide-by-sample-count happens on the CPU. A photo leaves the engine at full precision, before bloom and tonemap ever touch it.
  • Landed: the render CLI. main --photo out.exr --spp 1024 --bounces 6 warms the scene up (IBL capture, async loads), freezes the simulation, traces to the sample budget, writes a linear EXR plus a tonemapped PNG preview, and exits with a meaningful status code (0 written, 2 unavailable, 3 write failed, 4 aborted). --photo-wait is the compose mode: the demo boots into its main menu, so instead of freezing on a timer, play to the moment, frame the shot on the free camera, and press F9 — the trace starts from exactly that state. The EXR writer is in-repo (single-part scanline FLOAT, no compression, ~100 lines against the format spec) and locked by a round-trip test with an independent parser — one emitted variant did not justify a 12k-line vendored dependency.
  • Landed: CPU verification of the integrator math. The sampling functions are transliterated into test_path_tracer and tested statistically: the BSDF sampler's expected weight must match the numerically integrated reflectance (the property that keeps renders from silently coming out a constant factor too bright or dark), and a white surface must never reflect more energy than it receives, down to roughness 0.05. The transliteration must be kept in sync with the MSL by hand — the price of testing GPU math where no GPU exists.
  • Landed: analytic-light NEE for every light type — point, spot and rect join the sun (see the integrator section for the conventions and the derived rect radiance). A photo of an interior scene now converges to its actual lighting instead of pretending only the sun exists.
  • Next: depth of field — lens sampling at ray generation, which a path tracer gets essentially for free and a raster DoF pass can only approximate.
  • Next: MIS against hittable emissive quad proxies for rect lights, to cut the variance of their sharp reflections.
